# CO oxidation workflow: shared logic (draft)

**Scope.** Reusable order for supported nanocluster CO + O → CO₂ studies. This file records decisions and evidence gates. System-specific energies, job IDs, parameters and interpretations remain in campaign reports. Upstream O₂ dissociation and oxygen migration are separate paths; include them only when the proposed catalytic cycle needs them.

**Function convention:** Names below identify existing code, not automatic scientific validation. `jobs.*`, `core.mep_render` and `ingest.spectral` are under `reaction_hub/`; `active_learning_neb_workflow` is `cats/working_directory/active_learning_neb_workflow.py`; `nto_povray`, `multiwfn.tools`, `multiwfn.iroot_scoring` and `multiwfn.mep_state_tracker` are under `cats/multiwfn/`; `uvvis` is `cats/visualise/uvvis.py`; `ts_vibrations_gradient` is `cats/orca/routines/ts_vibrations_gradient.py`. Publish work through `jobs.tasks.enqueue_analysis_request` (or its `enqueue_*` wrapper); `_submit_*` functions are worker internals, never direct agent entry points. “Manual” means no dedicated repo function exists. Use database IDs and bounded options in Celery requests.

## 1. Define reaction and source lineage

1. Identify cluster, adsorption site, charge, spin multiplicity, electronic method and the two chemical endpoints.
2. Fix atom identities and fragment membership before comparing geometries: cluster, CO, and reacting O; merge CO₂ atoms only for the product-side IFCT definition.
3. Record source `WorkflowRun`, `JobRecord`, `HPCSystem`, geometry artifact and settings profile. State **chemical oxidation direction** independently of stored image order. Define the index mapping when a stored band runs CO₂ → CO + O.
4. Reuse completed equivalent calculations. Keep each derived run linked to its actual source geometry and wavefunction.

**Repo map (steps 1–4):** 1 manual chemistry/endpoint choice; 2 `jobs.views._infer_ct_fragment_defaults` proposes fragments, then verify atom IDs manually; 3 `jobs.tasks._get_run_image_atoms` reads a recorded image and `WorkflowRun`, `JobRecord`, `HPCSystem`, `Artifact` supply lineage; 4 manual database/artifact duplicate check before `jobs.tasks.enqueue_analysis_request`. Fragment inference and duplicate checking do not prove chemical equivalence.

**Gate:** reactant and product represent the intended chemistry with consistent atom order, method and charge. Do not compare unrelated facet, corner or migration paths as one continuous reaction coordinate.

## 2. Establish ground-state path

1. Optimise endpoint geometries when needed. If an interior image relaxes below a fixed endpoint, optimise that image independently and use the verified minimum as the new endpoint. Compare it with its exact source image using matched-view POV-Ray structures, key distances, energy and displacement. Record endpoint forces, source images and whether each endpoint was fixed or optimised in the MEP calculation.
2. Build an ordered band between matching endpoints and run the repository's DFT MEP route.
3. Read the **ingested** final band, energy and force arrays. Check every image: atom order, finite energy, force, adjacent atomic displacement, original C–O length, forming C–O length, O–Au contact and endpoint identity. For MLNEB, compare each final-band geometry with the evaluated-trajectory archive; label exact DFT evaluations and model-predicted images separately on the profile.
4. Require a continuous chemical path and an **internal** energy maximum before calling any image a band TS candidate. A scheduler-completed or algorithm-converged job can still fail this scientific gate. If an independently relaxed intermediate leaves the band, reconstruct the segment between that basin and the verified product minimum. Seed from ordered original images, add interpolation only where needed, and include a refined TS geometry where compatible. Re-run MEP; interpolation alone does not establish spring-force convergence. Repair and repeat until accepted.
5. Split a two-step route at a defensible intermediate. Relax that intermediate independently when its basin energy matters; retain both band-image and relaxed energies. Compare the relaxed geometry directly with its **actual source image** using matched-view POV-Ray structures and a short table of original/forming C–O and relevant metal–adsorbate distances. Record atom identities, energy change and geometry displacement; identify any changed adsorption contacts.
6. Show energy against image index and, directly beneath it, against cumulative atomic shift from the **same ordered, ingested band**. Use the existing `core.mep_render.compute_cumulative_atomic_shifts`: each step adds the Euclidean norm of all matched atomic-coordinate changes. If a relaxed intermediate leaves the band, compare its final geometry directly with its exact source band image; report the full configuration-vector shift and per-atom RMS in a **separate off-MEP panel**. Keep the relaxed point off both MEP curves. A connector between source and relaxed structures compares them; it is not a sampled relaxation trajectory or additional MEP path length.

**Repo map (steps 1–6):** 1 `jobs.tasks.enqueue_dft_optimisation` using source run/image IDs; 2 `jobs.tasks.enqueue_dft_mlneb` dispatches to `_submit_dft_mlneb`, which uses `active_learning_neb_workflow.run_active_learning_neb_workflow`; 3 `jobs.tasks._get_run_image_atoms` reads image coordinates, while energy/force and bond checks are manual; 4 no band-repair or scientific-acceptance function: prepare a reviewed seed trajectory Artifact, pass its ID to `enqueue_dft_mlneb`, then inspect ingested band; 5 `enqueue_dft_optimisation`, `_get_run_image_atoms`, `nto_povray.render_structure_povray`; 6 `core.mep_render.compute_cumulative_atomic_shifts`, `nto_povray.render_structure_povray`; profile/off-MEP panel assembly is report-specific. `_pad_mep_images` creates fixed optical snapshots, not a converged MEP seed.

**Gate:** an accepted path supports a signed oxidation coordinate, a reproducible energy profile and candidate saddle regions. Keep electronic band-image barriers separate from relaxed-basin barriers. Neither is a free-energy or rate constant. Complete this gate before using path geometries for UV-vis, IFCT or state tracking; preserve earlier analyses as historical when their path is superseded.

## 3. Refine and check stationary points

1. Refine each relevant internal band maximum with the existing dimer operation; preserve the parent MEP and image index. The highest point of a different segment is a different candidate.
2. Compare refined and source geometries and energies. Run ground-state frequencies on each refined candidate.
3. Call a structure a **verified first-order saddle** only with one chemically relevant imaginary mode aligned with the intended reaction. With two or more imaginary modes, the refined-TS minus relaxed-intermediate electronic $E_a$ remains a valid reported energy difference; label the structure a candidate and the kinetic interpretation provisional.
4. Confirm the mode sign against nearby MEP images before any force projection. A positive projection in stored dissociation direction is negative for oxidation.
5. Add each refined TS to the ground-state energy profile at its parent reaction coordinate with a distinct marker and `WorkflowRun` label. Plot its **refined energy**, even when it nearly coincides with the band image; identify the band maximum separately. Show a separately relaxed intermediate as a distinct point and label the corresponding electronic $E_a$.

**Repo map (steps 1–5):** 1 `jobs.tasks.enqueue_dimer_refinement` dispatches to `_submit_dimer_refinement` and `active_learning_neb_workflow.run_dimer_refinement_workflow`; 2 `jobs.tasks._get_run_image_atoms` reads parent image, `jobs.tasks.enqueue_ts_vibrations_gradient` requests frequencies; 3 `ts_vibrations_gradient.parse_orca_hess` reads modes, while saddle order and $E_a$ interpretation remain manual; 4 `ts_vibrations_gradient.run_ts_vibrations_gradient` computes projection, but oxidation sign and atom IDs need independent verification; 5 no shared refined-TS profile plotter: combine ingested energies manually, using `core.mep_render.compute_cumulative_atomic_shifts` for band abscissa.

**Gate:** frequency and direction checks precede a definitive TS or forward-driving claim. Ground-state path validation precedes excited-state mechanistic analysis.

## 4. Characterise fixed geometries optically

1. After accepting the optimised MEP and refined TS, choose a small geometry set: reactant, product, intermediate, each saddle candidate and enough original or padded MEP images to resolve changes near important regions. Padding adds **fixed-geometry** points; it does not repair an invalid MEP.
2. Run geometry-preserving TDA calculations using the campaign's recorded method. Record requested and **actual** root counts and verify wavelength coverage. A scan root setting and a final-spectrum root count can differ.
3. Reuse a matching completed TDA calculation for Multiwfn IFCT. Use the ORCA output and wavefunction from the **same** calculation and complete, non-overlapping fragment definitions.
4. For selected stationary geometries, follow [full charge-transfer workup](FULL_CT_WORKUP_PROTOCOL.md): Mulliken ground-state charges; optional frozen-fragment energy reference; vertical spectrum; per-root directional IFCT; bounded CDD/NTO analysis. Preserve Löwdin values under separate labels.
5. Store raw spectra, per-root oscillator strengths and IFCT terms. State whether a wavelength denotes a vertical root or a peak in a broadened spectrum.

**Repo map (steps 1–5):** 1 `jobs.tasks._pad_mep_images` supplies fixed snapshot padding inside `_submit_mep_uvvis_snapshots`; geometry choice remains manual; 2 `jobs.tasks.enqueue_analysis_request("mep_uvvis_snapshots", …)` dispatches to `_submit_mep_uvvis_snapshots`, and `uvvis.extract_uv_spectrum` reads spectra; 3 `jobs.tasks.enqueue_full_ct_workup` dispatches to `_submit_full_ct_workup_run`, and `multiwfn.tools.parse_ifct` parses IFCT output; 4 `enqueue_full_ct_workup` and `enqueue_analysis_request("density_analysis", …)` cover recorded workup stages; 5 `ingest.spectral.transition_data_from_dataset`, `write_ct_plot_artifacts`, and `write_broadened_plot_artifacts` expose ingested roots and plots. Check actual requested root count, matching wavefunction and fragment partition in run records.

**Gate:** completed and ingested numerical artifacts support each reported optical or charge-transfer value. A broad peak does not identify one electronic root.

## 5. Screen CT roots, then track selected states

1. At the refined saddle, use the important peaks already marked in the **300–800 nm CT spectrum**. Map each peak to its contributing vertical TDA root and order selected roots by **ascending excitation energy**. For WFR 9364, the illustrative sequence is S5 (719.6 nm), S6 (649.5 nm), then S8 (532.3 nm). Screen selected peaks, not every root.
2. Calculate an analytical excited-state gradient for each selected root in that order. Project its force onto a unit vector signed CO + O → CO₂. Select a product-favouring root and, if one exists, a reactant-favouring root. If no root favours one direction, record that result; do not invent a representative. An extra imaginary mode makes direction assignment provisional.
3. Starting from each selected saddle root, track **both ways** to the CO + O initial state and CO₂ final state. Root numbers may change along the path.
4. Compare NTO pairs, hole, electron and CDD spatial overlap at adjacent geometries. Record root changes, low-overlap links and avoided-crossing ambiguity. `nto_max_pairs=3` permits **up to** three leading pairs; it does not require three.
5. Add fixed-geometry points across a weak link, then rerun the comparison. Do not infer state identity from a repeated root number, similar wavelength or intensity alone.
6. Keep band intermediate and separately relaxed intermediate distinct. Directly compare their states before assigning the same lineage to both.
7. For each selected, sufficiently tracked branch on the accepted padded path, retain the winning CDD cube for **every ordered coordinate** and make a POV-Ray CDD progression GIF. Put the verified GIF in that campaign protocol beside its tracking plot; label oxidation direction, source run, starting root and frame-to-coordinate map. If any frame or state link is missing, show the gap and mark the full-path GIF pending. A GIF shows density evolution, not state continuity by itself.

**Repo map (steps 1–7):** 1 `ingest.spectral.transition_data_from_dataset` and `multiwfn.iroot_scoring.energy_from_wavelength_nm` expose root energies; marked-peak choice and ascending order are manual; 2 `jobs.tasks.enqueue_ts_vibrations_gradient` dispatches to `_submit_ts_vibrations_gradient_run` and `ts_vibrations_gradient.run_ts_vibrations_gradient`; independently check oxidation sign; 3 `jobs.tasks.enqueue_mep_state_tracking` dispatches to `_submit_mep_state_tracking_run` and `multiwfn.mep_state_tracker.ContinuousMEPTracker.run_tracking`; 4 `multiwfn.iroot_scoring.compute_state_spatial_overlaps` and `ContinuousMEPTracker.run_tracking` provide overlap evidence; 5 `jobs.tasks._pad_mep_images` creates fixed snapshot padding, then rerun `enqueue_mep_state_tracking` after relevant TDA/CT ingestion; 6 `enqueue_mep_state_tracking` with both recorded geometry-run IDs compares band and relaxed states; 7 `ContinuousMEPTracker.run_tracking` saves `mep_cdd_image_XX.cub`, then `ContinuousMEPTracker.render_cdd_animation` calls `nto_povray.write_cdd_pov_scene`/`render_pov_scene` and Pillow to write `mep_cdd_animation.gif`. Verify every cube, `.pov`, `.ini`, PNG and GIF frame in order; the renderer can skip failed frames. Ingest registered artifacts through `workflows.tasks.enqueue_artifact_ingest`. No function turns ambiguous overlaps into a proven state identity.

**Gate:** report local force direction and endpoint state continuity separately. State continuity requires supported spatial links; otherwise report unresolved gaps.

## 6. Interpret screened forces

1. Confirm that each TS gradient, CT root and reaction vector refer to the same refined geometry and method. Report projection sign, total and reacting-atom contributions, units and source root. For Au20 corner WFR 9371 S5, an independent signed-vector check gives a **local oxidation-directed force**; its stored `favours_bond_breaking` flag used wrong atom indices.
2. From the **accepted** reactant-side tracking branch, identify the root corresponding to each selected TS root at the initial geometry; do not copy the TS root number. Calculate its excited-state gradient at that exact initial geometry. Project the Cartesian force onto the unit vector from the initial to the **next accepted reaction coordinate** using matched atom order: $\Pi_{0\to1}=\mathbf F_{S_{n(0)}}\cdot(\mathbf R_1-\mathbf R_0)/\|\mathbf R_1-\mathbf R_0\|$. Report full-system and reacting-atom terms in eV/Å. Positive means local forward push; negative opposes; near-zero is inconclusive. Weak tracking links leave root correspondence provisional.
3. Local force projections at initial and TS geometries describe initial motion after vertical excitation. They do not establish propagation to the next coordinate, barrier lowering, product yield or rate. Relax excited-state minima separately when a same-surface barrier is needed.

**Repo map (steps 1–3):** 1 `ts_vibrations_gradient.parse_orca_engrad` and `run_ts_vibrations_gradient` supply gradient/projection data; source-root matching and reacting-atom sign check are manual; 2 `ContinuousMEPTracker.run_tracking` identifies the initial root, then existing `jobs.tasks.enqueue_analysis_request("ts_vibrations_gradient", {"source_run_id": initial_geometry_run_id, "iroot": tracked_initial_root, "nroots": …})` obtains its atomic forces. That route also calculates frequencies; its TS-mode projection is **not** the initial-path projection. Compute the signed first-segment projection independently from its `atom_forces_eV_A` and ingested coordinates. 3 `jobs.tasks.enqueue_analysis_request("targeted_tddft_optimisation", …)` requests an excited-state minimum. No repo function infers propagation, yield, rate or barrier lowering from a local projection.

**Gate:** no photochemical acceleration claim follows from UV-vis, IFCT or a local force projection alone.

## 7. Refine selected states on the excited surface

1. Use the **refined ground-state MEP TS geometry** as the starting structure. For each product-favouring root selected in Section 5, and each reactant-favouring root if present, enqueue a separate existing `dimer_refine` operation with that refined TS `source_run_id`, `backend="tddft"`, its **root number at the starting TS** as `root_state`, sufficient `tddft_scan_nroots`, the root wavelength as `target_wavelength_nm`, and the recorded fragment definition. Do not start from a band image or substitute a root number from an endpoint.
2. Record which ground-state imaginary mode initialises the dimer and how it aligns with oxidation. If the ground-state candidate has extra imaginary modes, identify the reaction-aligned mode explicitly and treat the resulting excited-state saddle assignment as provisional.
3. Check each completed excited-state dimer separately: convergence, final geometry, energy/curvature, and whether the intended electronic state remains identifiable along optimisation. Check excited-state saddle order when frequency data are available. A completed dimer job alone does not prove a first-order excited-state saddle.
4. Compare an excited-state barrier only against a corresponding minimum on the **same identified excited-state surface**. Keep this result separate from the vertical-force screen and the ground-state electronic barrier.

**Repo map (steps 1–4):** 1 `jobs.tasks.enqueue_dimer_refinement` dispatches to `_submit_dimer_refinement` and `active_learning_neb_workflow.run_dimer_refinement_workflow`; explicitly pass regular-queue settings when applicable because worker defaults may name an old reservation; 2 `ts_vibrations_gradient.parse_orca_hess` reads modes, while reaction alignment is manual; 3 `multiwfn.mep_state_tracker.ContinuousMEPTracker.run_tracking` checks electronic continuity, and `parse_orca_hess` supports a frequency check when output exists; 4 `jobs.tasks.enqueue_analysis_request("targeted_tddft_optimisation", …)` can provide a minimum candidate, but same-surface identity and barrier subtraction require manual verification.

**Gate:** retain source ground-state TS, selected root, excited-state dimer run, final structure and state-identity evidence in one lineage. If a selected direction has no root or the dimer fails, report that outcome without substituting another state.

## 8. Close evidence and figures

1. Record separately: Celery message accepted by `submissions`; scheduler job ID and state; database workflow state; local cache availability; artifact ingestion. Include status source and timestamp. A queued run is not a completed calculation.
2. Read HPC status, bounded logs and registered artifacts only through approved Celery operations, including `job_diagnostics` and existing artifact ingest. The user owns the persistent worker. Submit new analysis through existing `enqueue_analysis_request` operations such as `full_ct_workup`, `dimer_refine`, `mep_state_tracking` and `ts_vibrations_gradient`; use the established web submit flow for workflow submissions.
3. Link every number and figure to source geometry, workflow, job, artifact, settings and transformation. Render report **structure** figures with the established ASE scene export and POV-Ray workflow; verify rendered images before assembling panels.
4. Separate observation, inference and unresolved validation. Publish neither a failed MEP nor a candidate with extra imaginary modes as a verified reaction mechanism.

**Repo map (steps 1–4):** 1 `jobs.tasks.enqueue_analysis_request` returns Celery task ID; `WorkflowRun`, `JobRecord` and `Artifact` store distinct status/provenance, which must be read separately; 2 `enqueue_analysis_request("job_diagnostics", {"job_id": …, "tail_lines": 200})` and `workflows.tasks.enqueue_artifact_ingest` are approved remote-read/ingest entries; 3 `nto_povray.render_structure_povray` and `ingest.spectral.write_ct_plot_artifacts` produce structure/CT figures with source artifacts; 4 manual scientific judgement, no repo verdict function. Never call `jobs.submission.submit_slurm_workflow_run` from agent code.

## Figure selection and placement

- Place initial/product POV-Ray structures and structural MEP GIF beside ground-state path and energy profile. Put refined/candidate TS structure beside refinement and frequency evidence. Do not append a detached structure gallery.
- Show path-resolved UV-vis as **stacked spectra over the accepted MEP**, using `cats.visualise.uvvis.plot_uv_spectra_stacked`. The 2%-of-global-peak offset convention is illustrated in `reaction_hub/scripts/generate_au20_mep_figures.py`; use current campaign data, not its historical IDs. Preserve cached broadened line data when available. Label numeric reaction coordinates, direction, offset, source broadening and normalisation. Keep missing-coordinate gaps; an unshifted overlay is not the required stacked MEP figure.
- Main optical section shows **only initial, TS (or explicitly labelled candidate), and final CT spectra** for each single step. Arrange these CT panels vertically, one full-width plot per row, in initial–TS–final order; do not place them in side-by-side table columns. Intermediate-coordinate and separate directional CT galleries stay cached/supplementary unless requested. Reuse endpoint spectra only after exact geometry-lineage verification.
- Place CDD/NTO frames and padded CDD GIF beside state-tracking evidence. Distinguish structure animation from density animation. Never substitute a historical refined structure for a current-path TS without explicit lineage and labelling.

## Source reports and known cautions

**Repo map:** No report-verdict function. Read linked documents as dated evidence; verify current `WorkflowRun`, `JobRecord` and `Artifact` records before carrying any result into a new campaign.

- [Au20 corner MEP 3326](../../docs/au20_corner_co_oxidation_mep3326_protocol.md): reversed stored coordinate, separately relaxed intermediate, 3.809 eV electronic intermediate-to-refined-TS $E_a$, two imaginary modes, locally oxidation-directed S5/S6/S8 forces. Direct relaxed-intermediate-to-TS tracking completed but gave ambiguous state matches; excited-state saddle remains unverified. These findings are report evidence, not output of a workflow-verdict function.
- [Au20 facet MEP 3325](../../docs/au20_co_oxidation_mep3325_protocol.md) and [Au20 migration MEP 3788](../../docs/au20_surface_migration_mep3788_protocol.md): different path segments and source geometries. Do not transfer a root or gradient result between them without lineage proof.
- [Cu13 padded tracking](../../docs/cu13_co_oxidation_padded_mep_tracking_protocol.md): root reordering and `nto_max_pairs` limits; multiple imaginary modes invalidate a unique TS direction.
- [Au55 MEP 8763 audit](../../docs/au55_co_oxidation_mep8763_protocol.md): scheduler completion and algorithm convergence did not make a discontinuous, endpoint-dominated band valid.
- [Au20 UV-vis compilation](../../docs/au20_co_oxidation_mep_uvvis_protocol.md) mixes corner and facet examples and describes WFR 9371 as belonging to refined WFR 9327. Local WFR 9371 provenance identifies **corner WFR 9326** as its source, with two imaginary modes. Treat that compilation's TS and forward-acceleration claims as unresolved until corrected.

The linked `docs/` reports are local, campaign-specific records. This workflow defines shared order; verify current database and artifacts before using any report's status or number.
